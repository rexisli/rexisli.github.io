数位 DP（DigitDP 模板）

摘要

数位 DP 解决的是「统计 [0,N][0,N][0,N] 中满足某个逐位条件的数的个数」。它把数看成定长数字串，从高位到低位逐位决策，用记忆化把「已经自由的低位」合并。

模板只有两个布尔状态：@@limit@@（前缀是否还贴着上界）和 @@lead0@@（是否仍全是前导零）。本文要回答三个「为什么」：为什么记忆化只在 @@!limit@@ 时写、为什么 @@lead0@@ 必须进状态、以及加了「依赖历史」的条件后为什么必须加维度——这三处恰好是这套模板最常见的三个翻车点。

不加任何条件时 @@count() == N+1@@，这是自检模板最快的办法。

1 问题与记号

把 NNN 写成 LLL 位十进制串 d0d1…dL−1‾\overline{d_0d_1\dots d_{L-1}}d0​d1​…dL−1​​（d0d_0d0​ 为最高位，允许前导零补齐）。每个 x∈[0,N]x\in[0,N]x∈[0,N] 与一个 LLL 位串一一对应（前导零补齐），且约束「x≤Nx\le Nx≤N」等价于「字典序 ≤\le≤ ddd 串」。

于是「数 xxx」变成「数 LLL 位串」，从上到下逐位枚举即可。

2 状态设计

@@dfs(pos, limit, lead0)@@：已确定前 pospospos 位，返回「把剩余 L−posL-posL−pos 位补完，有多少种合法方案」。

  • pospospos：当前位置。终止于 pos=Lpos=Lpos=L，返回 1（该数合法）——合法性已在沿途的 @@continue@@ 里筛掉。
  • @@limit@@：前缀是否与上界完全一致。一致时当前位 ≤dpos\le d_{pos}≤dpos​，否则 ≤9\le9≤9。转移 @@next_limit = limit && (d == up)@@。
  • @@lead0@@：是否仍全是前导零。它是「数位」这个概念本身的一部分：数字 777 写成 000…007000\dots007000…007，那些 0 不是它的数位。若条件涉及「第几位」「相邻两位」「数位和」，就必须靠 @@lead0@@ 区分「真 0」和「补位 0」。

3 记忆化的合法性

这是模板里唯一「不看注释就一定写错」的地方。

引理 1（@@limit@@ 分支状态数）. limit=truelimit=truelimit=true 的状态只有一条链：(0,true)→(1,true)→⋯→(L,true)(0,true)\to(1,true)\to\dots\to(L,true)(0,true)→(1,true)→⋯→(L,true)，共 L+1L+1L+1 个。

证明. nextlimitnext_limitnextl​imit 为真当且仅当 limitlimitlimit 为真且 d=dposd=d_{pos}d=dpos​；一旦某位 d<dposd<d_{pos}d<dpos​，后续 limitlimitlimit 恒假。□\square□

所以 @@limit=true@@ 的状态不需要记忆化（数量极少），记忆也不省时间。

引理 2（自由状态与上界无关）. 若 limit=falselimit=falselimit=false，则 @@dfs(pos,false,lead0)@@ 的返回值与 NNN 的剩余位无关。

证明. limit=falselimit=falselimit=false 意味着前缀严格小于上界对应前缀，剩余位可任填 0∼90\sim90∼9，上界不再产生任何约束。□\square□

定理（记忆化正确）. 只对 !limit!limit!limit 的状态写入/读取 @@dp@@，则结果正确。

证明. 由引理 2，同一 (pos,lead0)(pos,lead0)(pos,lead0) 在 limit=falselimit=falselimit=false 下被多次到达时答案相同（转移只依赖 pos,lead0pos,lead0pos,lead0 与后续位，与 NNN 无关），故可复用；limit=truelimit=truelimit=true 从不读写，故不存在误用。□\square□

反过来就错：若把 limit=truelimit=truelimit=true 的答案也存进 @@dp[pos][lead0]@@，那么「贴着上界」的答案会被后续「已自由」的同 (pos,lead0)(pos,lead0)(pos,lead0) 读到，把上界卡死的结果当成自由结果——表现为答案偏小，且只在某些 NNN 上错。

4 计数的正确性

定理. 若条件只依赖「数位串」（对前导零的处理由 lead0lead0lead0 显式给出），则 @@DigitDP(N).count()@@ 返回 [0,N][0,N][0,N] 中合法数的个数。

证明. 双射 x↔x\leftrightarrowx↔ 定长串已由第 1 节建立；@@dfs@@ 枚举了所有满足前缀约束的串，且每个串唯一到达；pos=Lpos=Lpos=L 时计数 1 当且仅当沿途未被筛掉。□\square□

自检. 不加条件时 @@count() == N+1（（（[0,N]$ 共 N+1N+1N+1 个数）。这是零成本的正确性探针，换任何条件之前先跑一遍。

状态数：O(L⋅2⋅∣额外状态∣)O(L\cdot 2\cdot|\text{额外状态}|)O(L⋅2⋅∣额外状态∣)，每状态 O(10)O(10)O(10) 转移；limit=truelimit=truelimit=true 链贡献 O(10L)O(10L)O(10L)。

8 实现细节与易错点

  • 记忆化条件是 @@!limit@@，写反直接错（第 3 节）。
  • @@dp@@ 初值必须是 −1-1−1（或用 @@vis@@ 数组）：用 0 当「未访问」会把「答案为 0」的状态反复重算，严重时退化到指数级。
  • @@next_limit@@ 用 upupup 判：@@limit && (d == up)@@。写 @@d == digit[pos]@@ 在语义上也对，但和 upupup 混用最容易出错。
  • @@lead0$ 别漏：涉及「数的位数」「首位」「相邻位」的条件必须带上；只涉及「出现次数」的条件有时可以不区分（前导零补的 0 会被计入）——这时要显式决定补位 0 算不算，通常是算错。
  • N<0N<0N<0 要特判返回 0：@@to_string(-1)@@ 得到 @"-1"@，拆位后 −-− 变成负数字符，行为未定义。
  • @@digit[pos]@@ 已减过 ′0′'0'′0′（构造函数里），@@dfs@@ 里别再减。
  • 答案可能超 @@int@@：[0,1018][0,10^{18}][0,1018] 的计数可达 101810^{18}1018，@@res@@ 与 @@dp@@ 都用 @@long long@@；取模版按题意。
  • 多次询问要清 @@dp@@：每次 @@DigitDP(N)@@ 构造都重新 @@assign@@，模板已处理；但若把 @@dp@@ 提到类外复用，必须手动清空。
  • 终止条件 @@pos == len@@ 返回 1：若题目要求「正整数」，此处要判 @@lead0@@ 并返回 0。

对拍方式（本模板实测通过）：不带条件时对 N=0∼5000N=0\sim5000N=0∼5000 检查 @@count() == N+1$，再抽查 999999999999999999、10610^6106、123456789123456789123456789、214748364721474836472147483647；带「不含 4」时对 N=0∼5000N=0\sim5000N=0∼5000 与暴力枚举逐个比对。

9 扩展

区间 → 差分：[L,R][L,R][L,R] 一律用 f(R)−f(L−1)f(R)-f(L-1)f(R)−f(L−1)（上面 @@DIFF@@ 那段）。

位数很大（L≤1018L\le10^{18}L≤1018）. 状态转移与位置无关时（例如「数位和模 3」+「不含 4」），把转移写成矩阵，用矩阵快速幂算「自由状态填 kkk 位的方案数」，O(∣状态∣3log⁡L)O(|\text{状态}|^3\log L)O(∣状态∣3logL)。

多串约束. 「不含子串 42」这类条件可以在数位 DP 上叠一个 AC 自动机（或 KMP 自动机），状态里带上自动机结点。

贡献法. 求「所有合法数的数位和之和」时不必在建状态里存和，可以逐位算「该位为 ddd 的方案数 × d⋅10kd\cdot10^{k}d⋅10k」，把计数 DP 复用成贡献 DP。

递推写法. 记忆化搜索与「按位递推 g[pos][...]g[pos][...]g[pos][...]（自由后缀方案数）」等价，后者常数更小但对 lead0lead0lead0 的处理更绕，OI 里更常用记忆化。
