## 适用场景

每种物品**有数量上限** $c_i$ 的背包问题——「第 $i$ 种物品最多买 $c_i$ 个，每个体积 $w_i$、价值 $v_i$，背包容量 $V$，求最大价值」。

朴素做法是把一种物品拆成 $c_i$ 个独立的 0/1 物品，复杂度 $O(Vsum c_i)$，$c_i$ 一大就废了。

## 思路：二进制拆分

把数量 $c$ 拆成 $1, 2, 4, \dots, 2^{k-1}, c - (2^k - 1)$ 这若干「块」，每一块当成一个 0/1 物品，体积和价值都乘以块的大小。

为什么对？因为这串数可以**拼出 $0 \sim c$ 之间的任意整数**：$1,2,4,\dots$ 能拼出 $0 \sim 2^k-1$，剩下的余数 $r = c-(2^k-1) \le 2^k$，与前面组合就能覆盖 $0 \sim c$。

于是「选 $x$ 个第 $i$ 种物品」这件事，就等价于「从这些块里挑一个子集」，正好是 0/1 背包，每个块只决策选或不选。

## 代码

拆分部分（原笔记代码，修正了手抄笔误，见下方易错点）：

```cpp
vector<vector<pair<int, int>>> bags(n + 1);
for (int i = 1; i <= n; i++) {
    int w, v, c;
    cin >> w >> v >> c;
    int base = 1;
    while (c) {
        int t = min(base, c);
        bags[i].emplace_back(t * w, t * v);  // first=体积, second=价值
        c -= t;                              // ← 注意是减去「件数」，不是 t * w
        base <<= 1;
    }
}
```

拆完之后就是对每个物品枚举它拆出的所有块，做一遍 0/1 背包：

```cpp
// V 为背包容量
vector<long long> f(V + 1, 0);
for (int i = 1; i <= n; i++) {
    for (auto &[w2, v2] : bags[i]) {
        for (int j = V; j >= w2; j--) {
            f[j] = max(f[j], f[j - w2] + v2);
        }
    }
}
cout << f[V] << endl;
```

## 复杂度

拆分后块数为 $\sum_i \lceil \log_2(c_i + 1) \rceil$，总复杂度 $O\!\left(V\sum_i \log c_i\right)$，比 $O(V\sum c_i)$ 快一个量级。

## 易错点

- **`c -= t` 别写成 `c -= t * w`**。原笔记里这里写的是 `c -= t * w`，会让 `c` 变成负数，`while (c)` 对负数仍然成立，于是 `t = min(base, c)` 取到负数、块越拆越多，实测直接 `std::bad_alloc` 爆内存。减的是**件数**。
- 块存的是 `(t * w, t * v)`——体积和价值都要乘块大小，只乘一个就会错。
- `bags` 开成 `n + 1` 是为了下标从 1 开始，循环里别写成 `bags[i - 1]` 弄混。
- 容量大的时候 `f` 用 `long long`，`t * v` 也可能溢出 `int`。
- 二进制拆分只适用于**同种物品价值相同**的情况；如果是「多类不同物品各自限量」就直接是分组背包了。

## 对拍验证

和「把 $c_i$ 件逐个当成 0/1 物品」的朴素写法在随机数据（$n \le 5$、$c_i \le 5$、$V \le 30$）上对拍 400 组，逐容量比较全部一致。
